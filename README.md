# SnakeScale Notes

![SnakeScale Notes logo](logo.png)

A free, open source, web based notes app inspired by the way Evernote works, with one big difference: your notes live in storage you own, not on our servers. There are no SnakeScale servers. The app is a single HTML file that runs entirely in your browser. At setup you choose where your notes live: your own Google Drive, or your own private GitHub repository.

Live app: https://clytherin-tech.github.io/snakescale/

## Why SnakeScale

- Free forever. The app is open source and your storage is your own Google or GitHub account.
- Private by design. Notes are stored as plain Markdown files in a Drive folder or a private repo that only you control.
- Works anywhere. Any modern browser on PC, tablet, or phone. No install required.
- Your data is yours. Export any time by downloading the files. It is just files.

## Features

- A real storage choice at setup (new in v1.4): Google Drive is recommended for most people. Sign in with Google once and your notes and attachments live in your own Drive, with no GitHub account and no token to paste. GitHub remains fully supported for power users who want a private repository and full Git version history, and it stays the default for vaults created before v1.4
- Notebooks, notes, and tags, with local full text search
- Rich text editor with headings, lists, and checklists
- Clickable, editable links in notes (v1.3.1, reworked in v1.3.2): Ctrl+click (Cmd+click on a Mac) opens a link in a new tab, and a plain click shows a small link popup where the address itself is clickable to open the link, and an Edit button lets you change that link's text or address in place. Only http, https, and mailto links can be opened or saved
- A full formatting toolbar (new in v1.3): an Insert menu (attachments, links, checklists, dividers, date and time), text styles (headings 1 to 3, quote, code block), font family and font size pickers, text and highlight color palettes with custom colors, strikethrough, text alignment, indent and outdent, and remove formatting. Fonts, sizes, and colors are saved as inline CSS styles in the note body, never as font tags, so formatted notes render the same on every device
- Attachments and inline images (new in v1.2): files are stored in your own Google Drive or pCloud account, in a folder named SnakeScale Notes Attachments, and your notes keep only a small reference to each file. You pick the provider in the app, sign in with OAuth (Sign in with Google or Sign in with pCloud), and attach from the Insert menu, by drag and drop, or by pasting an image. When Google Drive is also your notes storage, the same single Google sign in covers notes and attachments. Publisher setup for the sign in buttons is a one time job for the app owner: see [ATTACHMENT_PROVIDERS_SETUP.md](ATTACHMENT_PROVIDERS_SETUP.md). End users never register a developer app.
- Attachments where you left the cursor (new in v1.6): files attached from the Insert menu or file picker are inserted at the caret position you had when you started attaching, and files dropped onto the editor land at the drop point. A run of several files inserts in order at that spot
- Inline PDF preview (new in v1.6): PDF attachments get a Preview toggle on their card. Expanding it fetches the document on demand and shows it right inside the note, in the place where the attachment sits, so a PDF can be read without downloading it first. The preview is view only state; it is never written into the saved note file
- Movable, resizable attachments (new in v1.6): attachment blocks can be dragged to a new position inside a note (on touch screens, cut and paste moves them instead). Clicking an inline image selects it and shows a corner handle; dragging the handle resizes the image, and the chosen width is saved in the note so it renders the same size on every device
- Undoable attachment deletion (new in v1.7): removing an attachment, from its Remove button, the image menu, or the Delete and Backspace keys, takes it out of the note at once and opens a five second undo window, announced by a toast at the top of the window with the file name and an Undo button. The file is deleted from your cloud storage only when the window closes; Undo (or the block coming back, for example through the editor's own undo) cancels the deletion completely, and if the cloud delete cannot happen the attachment is restored and kept
- Inline images, no card (new in v1.7): image attachments sit in the note as plain images in the text, with no border, no card frame, and no name bar. File attachments, including PDFs with their inline preview, keep the card look
- Image grips and a three dot menu (new in v1.7): clicking an image selects it with four corner grips for resizing (any corner works, proportions are kept) and a three dot button at its top right. The menu opens the image full size, downloads it, applies quick sizes (25, 50, or 100 percent of the note column), or removes it through the undoable deletion above. A freshly pasted or dropped image can be selected, moved, and resized right away, without reopening the note
- Checklists without bullets, with real Enter behavior (fixed in v1.6): checklist items no longer show a stray list bullet in front of the checkbox, and pressing Enter at the end of a checklist item starts a fresh checklist item. Enter on an empty checklist item leaves the checklist, like other note apps
- A branded loading screen (new in v1.6): an animated tile S logo with a plain status line covers sign in and sync, and the note list fills in from the device cache behind it, so connecting never means staring at a blank screen. The sidebar shows the running app version at the bottom
- Pinned notes, trash with restore, and delete forever
- Archive (new in v1.5): tuck notes out of the way without deleting them. Archived notes move to their own archive folder and Archive view, stay out of the regular lists and search, open read only, and unarchive back to the notebook they came from at any time. Moving a note to Trash, restoring it, and deleting it forever also update the screen instantly now, with the storage work finishing in the background
- Local encryption that matches the backend: GitHub storage uses an app password vault in your browser (PBKDF2 plus AES-GCM), and its token and provider OAuth tokens are stored only as ciphertext. Google Drive storage has no app password; a random device key encrypts provider tokens and the local note cache on that device. That device key is not a login and does not protect against someone using your unlocked browser profile
- Offline reading and editing from the local cache, with queued changes synced when you reconnect
- Conflict safety on both storage backends: if a note changed somewhere else, saving creates a conflict copy instead of overwriting it
- Light and dark themes in the Deep Forest palette

## How to use it

Choose one storage option at setup. The choice is stored on that device.

### Option A: Google Drive (recommended)

1. Open the live app link above.
2. On the setup screen, choose Google Drive and continue. There is no SnakeScale app password for Drive storage.
3. Click Sign in with Google and approve access. Google sign in is the only sign in. SnakeScale creates a folder named SnakeScale Notes in your Drive for your notes. Attachments use the separate SnakeScale Notes Attachments folder, with the same sign in.
4. Start writing. On later visits SnakeScale first tries a silent Google sign in renewal; if that is not available, it shows the Sign in with Google screen. Use Sign out in the sidebar to clear this device's local copies, provider sign ins, and device key while leaving the Drive notes untouched.
5. On other browsers, repeat the setup and sign in with the same Google account.

### Option B: GitHub (advanced, with version history)

1. Open the live app link above.
2. Create a GitHub personal access token (classic) with the repo scope checked, name it something like SnakeScale so you remember what it is for.
3. In the app setup screen, choose GitHub, paste the token, and choose an app password. The token is encrypted with that password and kept only in that browser.
4. Leave the data repo name as snakescale-notes-data, connect, and let the app create the private data repo for you.
5. Start writing. Repeat the quick setup in any other browser where you want your notes.

## How your data is stored

Both backends use exactly the same layout and the same note file format. Only the service holding the files differs.

- A root container you own: the SnakeScale Notes folder in Google Drive, or your private data repository on GitHub
- One folder per notebook inside a notebooks folder
- One Markdown file per note, with simple front matter and an HTML body
- A trash folder for deleted notes, an archive folder for archived notes, and an index.json the app can rebuild from the folders at any time
- Attachments are different on purpose: the binary files live in your Google Drive or pCloud account, in the SnakeScale Notes Attachments folder. The note file stores only a one line attachments list in its front matter (provider name and file ID) plus a placeholder in the body where the image or file card appears

## Privacy and security notes

- With Google Drive storage, note sync talks to Google Drive from your browser, and Google's sign in script is loaded from Google only at the moment you click Sign in with Google. SnakeScale can only see the Drive files it created (the drive.file permission), not your whole Drive.
- The app ships with the publisher's Google OAuth client ID built in (new in v1.4.2), so nobody is ever asked for a client ID. That ID is a public identifier, not a secret: Google locks its use to the web origins the publisher registered in Google Cloud, so it cannot be used to sign anyone in from anywhere else. If you fork SnakeScale, register your own OAuth client in Google Cloud (free) and either replace the PUBLISHER_GOOGLE_CLIENT_ID constant in the app file, or enter your ID in the advanced override field in the Attachments settings dialog.
- With GitHub storage, note sync talks only to api.github.com from your browser.
- If you use attachments, the app also talks to the storage provider you signed in to (Google or pCloud). With GitHub storage, provider tokens are stored in your browser encrypted with the same app password as the vault, never in plain text. With Google Drive storage, they are encrypted with the random device key described above.
- Local copies on a Google Drive device are encrypted with that device key, but the key lives on the same device. It scrambles local copies against casual snooping; it is not a login and it does not protect against someone using your unlocked browser profile. Sign out clears those local copies.
- Anyone with your GitHub token has the access that token grants, so use a token you can revoke, and lock the app when you step away.
- SnakeScale Notes is not affiliated with Evernote Corporation.

## Current status

Version 1.8.0, build stamp 2026-10-19-SSN-V180. New in this release: a toolbar for the notes list. Under the list title and note count sits a right aligned row of four icon buttons. New Note creates a note in the current notebook (the default notebook in the combined views, and disabled in Trash and the Archive). Filters open a panel with tag checkboxes (a note must carry every checked tag), plus From and To date pickers for the created and updated dates, compared by local calendar day with either end open; filters combine with the current view and the search box, stay in place across views until cleared, and light the Filters button while any is set. Sort and display sorts by Title, Date Created, or Date Updated, each with a direction, and the choice is remembered between sessions; the default stays Date Updated, newest first, and pinned notes still lead the list. A notebook menu holds Rename Notebook and Delete Notebook, the flows that used to hide as hover links on the sidebar notebook rows; those hover links are removed. The previous release (v1.7.2) added free image sizing. An image in a note can now be sized to any width, narrower or wider than the note column: the grip drag no longer clamps to the column, a sized image carries no width cap, and the editor pane scrolls sideways for images wider than the column. The chosen size now lives on the image's block rather than on the image itself, so the selection grips and outline track the image exactly as it grows or shrinks (in v1.7.0 and v1.7.1 the size lived on the image and a shrunken image's frame did not reliably follow). Notes saved by v1.6 or v1.7 display at the same size as before and save forward in the new form the next time they are edited. The image menu also gains an Original size preset, which sets the image to its natural width, beside the existing 25, 50, and 100 percent of column presets. The previous release (v1.7.1) fixed the image selection frame: in v1.7.0 the four corner grips, the selection outline, and the three dot menu button sat at the edges of the whole note column for any image narrower than the column, because the block around the image still spanned the full column width; image blocks now shrink wrap the image itself, so the grips, the outline, and the menu button sit on the image's own corners at any image width. The previous release (v1.7.0) added: attachment deletion is undoable. Removing an attachment (its Remove button, the image menu, or the Delete and Backspace keys) takes it out of the note at once and opens a five second undo window, announced by a toast at the top of the window naming the file with an Undo button; the cloud file is deleted only when the window closes, Undo or the block coming back on its own cancels the deletion outright, and if the cloud delete cannot happen the block is restored and the attachment is kept. Images now sit in the note as plain inline images with no card frame and no name bar, and clicking one selects it with four corner resize grips plus a three dot menu at its top right (Open, Download, quick sizes at 25, 50, or 100 percent of the note column, and Remove). A freshly pasted or dropped image can be selected, moved, and resized immediately, because insertion, hydration, and rendering now share one decoration pass. The previous release (v1.6.0) added: a branded loading screen with an animated tile S logo and a status line covers boot and connect flows while the note list fills in from the device cache behind it; attachments are inserted at the cursor position (or at the drop point for drag and drop) instead of wherever the caret happened to end up; PDF attachments can be previewed in line inside the note, fetched on demand and never saved into the note file; attachment blocks can be dragged to a new position within a note, and inline images can be resized with a corner handle, with the chosen width saved in the note; checklists no longer show a bullet in front of the checkbox and Enter at the end of a checklist item starts a new checklist item; and the sidebar shows the app version at the very bottom. The previous release (v1.5.1) fixed three interface issues from live testing: toast notifications now appear above the editor's bottom right action buttons instead of covering them, the Insert menu no longer repeats Checklist (the toolbar keeps its own checklist icon button), and the New Note button fits inside the sidebar instead of spilling past its edge. The previous release (v1.5.0) brought instant deletes and note archiving: moving a note to Trash, restoring it, and deleting it forever used to wait on the storage round trips before the screen changed (a write to the new folder plus a delete of the old file); the screen now updates the moment the action is taken and the storage work finishes in the background, under the same failure messages and offline queue rules as before. Every storage operation on one note now runs through a single per note operation chain, so a rapid sequence of actions on the same note (save, trash, restore, archive) reaches storage in the order it was clicked. Archiving is new: an Archive button on any note tucks it into an archive folder in your storage and an Archive view in the sidebar; archived notes stay out of All Notes, notebook and tag views, Pinned, and search, they open read only like trashed notes, and Unarchive returns a note to the notebook it was archived from. Moving an archived note to Trash keeps that original notebook as its restore target. The previous release (v1.4.4) made note and notebook creation faster: a new note or notebook appears and opens immediately while its upload runs in the background, instead of waiting on a chain of storage calls first (on Google Drive that wait took a few seconds); saves of one note were serialized per file path so a background create could never be overtaken by the first autosave of an edit, brand new files skip the existence check listing on Drive, and index writes are coalesced so a burst of changes costs at most one in flight write plus one follow up. The release before that (v1.4.3) fixed Google Drive library loading and first run seeding: library loading and sync no longer require a GitHub token, which Drive users (Google sign in only) never had, so a Drive library now loads on every browser after sign in, and notes saved during the affected releases were stored in Drive all along and appear once the fix loads them; seeding (the Personal notebook and the welcome note) is decided from the store itself rather than from when the Drive folder was created, so an interrupted first setup is repaired on the next sign in instead of leaving an empty library. The release before that (v1.4.2) baked the publisher Google client ID into the app, so no user is ever asked for a client ID: the Google sign in screen is just the sign in button, and every Google sign in (notes storage, silent renewal, attachments) uses the built in ID unless an advanced override was saved in the Attachments settings dialog for testing or for a fork. The release before that (v1.4.1) made Google Drive storage sign in only, with no SnakeScale app password: a device key replaces the old password derived key for local encryption, returning Drive users get a silent renewal attempt before the Google sign in screen, old v1.4 Google marker vaults are ignored and removed, and the sidebar Lock button becomes Sign out for Drive users. GitHub storage, including its app password vault, is unchanged for existing users and remains the default for vaults created before v1.4. Known limits: the storage backend cannot be changed after setup without resetting SnakeScale on that device, and there is no migration tool yet, so moving notes between Google Drive and GitHub is not supported in this release; Google sign ins expire after about an hour (the browser token flow gives no refresh token), silent renewal depends on the user's Google session and browser cookie behavior, and when it is not available the sign in screen appears for a one click sign in; edits made while a Google sign in is expired are kept in the sync queue rather than lost; the Google device key does not protect against someone using an unlocked browser profile; the formatting toolbar builds on the browser's built in editing commands, whose exact behavior varies a little between browsers; the pCloud browser download path follows pCloud's published API but is untested against a live account until the publisher test in the setup guide is run; attachments need an internet connection, with a 100 MB per file cap; and there is still no service worker, so it is not installable as a full PWA. That is planned for a later release.
