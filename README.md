# SnakeScale Notes

![SnakeScale Notes logo](logo.png)

A free, open source, web based notes app inspired by the way Evernote works, with one big difference: your notes live in storage you own, not on our servers. There are no SnakeScale Notes servers. The app is a single HTML file that runs entirely in your browser, and your notes live in your own Google Drive.

Live app: https://clytherin-tech.github.io/snakescale/

## Why SnakeScale Notes

- Free forever. The app is open source and your storage is your own Google account.
- Private by design. Notes are stored as plain Markdown files in a Drive folder that only you control.
- Works anywhere. Any modern browser on PC, tablet, or phone. No install required.
- Your data is yours. Export any time by downloading the files. It is just files.

## How to use it

1. Open the live app link above.
2. On the setup screen, continue to Google sign in. There is no SnakeScale Notes app password and nothing to fill in.
3. Click Sign in with Google and approve access. SnakeScale Notes creates a folder named SnakeScale Notes in your Drive for your notes, and attachments live in an attachments subfolder of that same folder, with the same sign in.
4. Start writing. On later visits SnakeScale Notes first tries a silent Google sign in renewal; if that is not available, it shows the Sign in with Google screen. Use Sign out in the sidebar to clear this device's local copies, the stored sign in, and the device key while leaving the Drive notes untouched.
5. On other browsers, repeat the setup and sign in with the same Google account.

## How your data is stored

Everything lives in one folder in your Google Drive, named SnakeScale Notes.

- One folder per notebook inside a notebooks folder
- One Markdown file per note, with simple front matter and an HTML body
- A trash folder for deleted notes, an archive folder for archived notes, and an index.json the app can rebuild from the folders at any time
- A catalog.json (new in v2.20.0): a small cache of everything the notes list displays (title, notebook, tags, preview, pin, thumbnail facts, and each note file's current revision), so loading the library reads one small file plus the folder listings instead of downloading every note body; a note's body is fetched when you open it or an operation needs it. The catalog is a cache only: the app rebuilds it from the note files whenever it is missing, damaged, or out of date, and the note files remain the only source of truth
- An incoming.json (new in v2.20.0): the drop box for notes added by other tools, documented under "Adding notes from other tools" below. It holds two lists, notes waiting to be imported and rejected entries, and stays empty until a tool writes into it
- A tasks.json (new in v2.24.0): every task in every notebook, in one small file the app keeps in step as tasks change. It is created the first time a task changes; a store with no tasks yet simply has no tasks.json. See the Tasks section below
- A versions folder (new in v2.8.0) with one JSON file per note holding that note's saved version history: previous titles, bodies, tags, and attachment references, newest first. The folder is created only when a note first gains a version, and index rebuilds ignore it just like the attachments folder
- Attachments are different on purpose: the binary files live in an attachments subfolder of the same SnakeScale Notes folder. The note file stores only a one line attachments list in its front matter (provider name and file ID) plus a placeholder in the body where the image or file card appears
- Upgrading from a version before v2.0: attachments used to live in a separate top level folder named SnakeScale Notes Attachments. Those files keep working where they are, because notes reference them by Drive file ID. On your first sign in after the upgrade, SnakeScale makes one best effort pass to move them into the new attachments subfolder; the old folder is left in place for you to remove when you are ready

## Tasks

Tasks (new in v2.24.0) are real to-dos that live alongside your notes, modeled on the way Evernote implements its Tasks feature and adapted to notebooks. A task is its own object, not a line inside a note: it belongs to a notebook, and it carries a title, an optional longer description, a due date with an optional time, a flag, a priority (low, medium, or high), a recurrence (none, daily, weekly, monthly, or yearly), and an optional reminder. Checklists inside notes are unchanged; tasks are the layer above them, for the things that carry dates and deserve a reminder.

Where tasks show up:

- In a notebook's list, and in All Notes, each notebook that has tasks gets one Things to do tile (new in v2.24.3, replacing the Tasks group the list carried through v2.24.2): a card like a note card, titled Things to do, with the notebook's name and its latest task activity in the meta line and a small pill showing how many of its tasks are completed out of the total. The tile sorts into the list by that activity time, like a note by its edited time. Clicking it opens that notebook's Things to do page in the editor: a breadcrumb, the same progress chip, a quick add for the notebook, and the tasks as a checklist with round checkboxes, word due labels at the right (Overdue in red, Due today, Tomorrow, or the date), the flag and the priority, and the completed tasks below their own heading, struck through and dimmed. Ticking a checkbox completes the task without opening anything (a recurring task rolls forward instead); clicking a row opens the task editor. The page is a view over the tasks only: it is not a note, and opening it writes nothing to any note file.
- The sidebar gains a Tasks entry directly under All Notes, with the open task count. The Tasks view lists every task in every notebook. It groups by due date (Overdue, Today, Upcoming, No due date, Completed), by notebook, or by priority, and filters to All, Open, Flagged, or Completed. A quick add row at the top creates a task in the notebook you pick; the New Task button beside it opens the full editor. Since v2.24.1 the Tasks view has its own pane: it takes the whole main area beside the sidebar while it is active (the notes list and the editor hide, and return untouched when you leave), its header shows the open count beside the title with a Find tasks search that filters the rows by title or notebook name, and its list is a table with a Title, Due date, and Notebook column header row and group headers that collapse and expand from a chevron.
- Completing a recurring task does not close it: its due date rolls forward by the interval (a monthly task due on the 31st lands on the last day of the next month), ready for its next round. Completing a plain task moves it to the Completed group, and unticking it there reopens it.

All tasks live in one file, tasks.json, in the same SnakeScale Notes folder as index.json, catalog.json, and incoming.json (notebook folders hold notes only, as always). The app reads it with the library, writes it as tasks change, and syncs it like the rest of the store, so tasks follow you across devices. If the file is damaged, the app shows an empty task list rather than failing, and it does not overwrite the damaged file until you actually change a task. Deleting a task removes it outright; there is no task trash in this version.

Reminders are notifications, generated on your device. When a task has a due date you can set a reminder for the due moment itself, 15 minutes or an hour before it, or a day before; a task with a due date but no time is due at 9:00 AM that day. The first time you set one, the app asks your browser for notification permission (there is also an Enable notifications button in the Settings Notifications section, which is also where the whole reminder feature can be switched off). While the app is open on a device, a scheduler checks every 30 seconds, and a due reminder appears as a notification naming the task, its notebook, and when it is due; clicking it focuses the app and opens that task's editor. Two honest limits: there is no SnakeScale Notes server and no push service, so a reminder cannot reach a device where the app is fully closed. What the app does instead is catch up: a reminder whose moment passed while the app was closed fires once when you next open it, and never twice for the same due moment.

Like everything else in SnakeScale Notes, tasks are plain data in your own Drive: anything with write access to the folder can read or edit tasks.json, and the format is the one described above.

## Adding notes from other tools

SnakeScale Notes signs in with the drive.file permission, which means Google only ever shows it files the app created itself. A note file another program uploads into a notebook folder is invisible to the app, and no index or catalog entry can change that.

The drop box works around it. incoming.json, in the same SnakeScale Notes folder, is a file the app creates and can always read, so anything with write access to that folder can add notes by editing its content:

- The file is a JSON object with two arrays: { "notes": [...], "rejected": [...] }.
- Each entry in "notes" is one complete note file as text: the same front matter and HTML body the app writes into a note's .md file (id, title, notebook, tags, created, updated, pinned, then the body after the closing front matter line). The notebook value must be the slug of a notebook that exists; an entry naming a missing notebook is imported into the first notebook instead, and the import report says so.
- On each sync the app imports new entries as ordinary notes it creates itself, removes them from "notes", and reports the counts on screen. An entry whose note id already exists anywhere in the store (notebooks, Trash, or Archive) is skipped as a duplicate and removed. An entry that is not note file text moves to "rejected" with a short error and the time, and is not tried again; fix the text there and move it back to "notes" to retry it.
- Attachment references in an entry's own front matter are removed on import, because the files they name are not visible to the app, and the import report counts the notes it happened to. Files themselves travel with the object entry form below instead.
- An entry may instead be an object: { "note": "<one complete note file as text, exactly as above>", "attachments": [ { "name": "photo.png", "mimeType": "image/png", "dataBase64": "<the file's bytes, base64 encoded>" } ] }. On import the app uploads each carried file itself, so it lands in the attachments folder as an ordinary attachment of the note: images are placed inline at the end of the body, and other files as attachment blocks there, in the order listed. Caps: 10 MB per attachment (decoded size) and 25 MB of attachments per entry (decoded). An item over a cap is skipped, and an item whose upload fails is skipped too, while the note and its remaining attachments still import. The import report counts the attachments imported, and names the ones skipped as too large and the ones that failed. The duplicate check runs before any upload, so reprocessing an entry never leaves orphaned files behind.

## Privacy and security notes

- Note sync talks to Google Drive from your browser, and Google's sign in script is loaded from Google only at the moment you click Sign in with Google. SnakeScale Notes can only see the Drive files it created (the drive.file permission), not your whole Drive.
- The app ships with the publisher's Google OAuth client ID built in (new in v1.4.2), so nobody is ever asked for a client ID. That ID is a public identifier, not a secret: Google locks its use to the web origins the publisher registered in Google Cloud, so it cannot be used to sign anyone in from anywhere else. If you fork SnakeScale Notes, register your own OAuth client in Google Cloud (free) and either replace the PUBLISHER_GOOGLE_CLIENT_ID constant in the app file, or set an override in the app settings value state.attach.googleClientId, which sign in still honors (there is no settings field for it in the app).
- Local copies on a device are encrypted with that device's random key, but the key lives on the same device. It scrambles local copies against casual snooping; it is not a login and it does not protect against someone using your unlocked browser profile. Sign out clears those local copies.
- Link info lookups (new in v2.9.0): when a link is shown as a Mention or a Preview, SnakeScale Notes looks up that link's address through Microlink (api.microlink.io) to fetch the page's title, description, cover image, and site logo. Only the link address is sent, never note text or Drive data. The result is saved in the note itself, so a link is looked up once, not on every view, and Text links are never looked up.
- Image transcription (new in v2.11.0): the image menu's Transcribe loads the Tesseract.js OCR library from the jsDelivr CDN the first time it is used, and only then. The recognition itself runs entirely in your browser on the image you chose; the image and its text are never sent anywhere. Nothing about it is loaded at startup, and it needs an internet connection only for that first library download.
- Settings or storage left on a device by a version before v2.0 (including an old app password vault record) are cleaned up automatically on first load; your Google settings, cache, and notes are not affected.
- SnakeScale Notes is not affiliated with Evernote Corporation.
- The published [Privacy Policy](https://clytherin-tech.github.io/snakescale/privacy.html) and [Terms of Service](https://clytherin-tech.github.io/snakescale/terms.html) live in this repo as privacy.html and terms.html.
