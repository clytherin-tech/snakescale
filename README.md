# SnakeScale Notes

![SnakeScale Notes logo](logo.png)

A free, open source, web based notes app inspired by the way Evernote works, with one big difference: your notes live in storage you own, not on our servers. There are no SnakeScale servers. The app is a single HTML file that runs entirely in your browser, and your notes live in your own Google Drive.

Live app: https://clytherin-tech.github.io/snakescale/

## Why SnakeScale

- Free forever. The app is open source and your storage is your own Google account.
- Private by design. Notes are stored as plain Markdown files in a Drive folder that only you control.
- Works anywhere. Any modern browser on PC, tablet, or phone. No install required.
- Your data is yours. Export any time by downloading the files. It is just files.

## Features

- One simple storage story (simplified in v2.0): sign in with Google once and your notes and attachments live in your own Google Drive, in one folder named SnakeScale Notes. There is no storage choice to make, no token to paste, and no app password. Earlier versions also offered a GitHub repository backend and a pCloud attachment provider; both were removed in v2.0 so the app has exactly one sign in and one folder
- Notebooks, notes, and tags, with local full text search
- Rich text editor with headings, lists, and checklists
- Clickable, editable links in notes (v1.3.1, reworked in v1.3.2, rebuilt in v2.9.0): Ctrl+click (Cmd+click on a Mac) opens a link in a new tab, and resting the mouse on a link (or clicking or tapping it) shows a dark link bar where the address itself is clickable to open the link, and icon buttons edit the link's text or address in place, copy the address, or remove the link while keeping its text. Only http, https, and mailto links can be opened or saved
- Link display modes (new in v2.9.0): the link bar's three dot menu switches a link between Text (an ordinary link), Mention (an inline chip with the site's logo and title), and Preview (a block card with the page's cover image, title, and description), and can also copy the address or delete the link and its text together. The mode is saved in the note itself. Mention and Preview fetch the page's real title, description, image, and logo the first time they are used on a link; see the privacy notes
- Links to other notes (new in v2.1.0): the Insert menu's Link to Note opens a searchable picker of your notes, and the link it inserts opens that note inside the app, switching the list to All Notes when the target is not in the current view. A link whose target sits in Trash or the Archive, or no longer exists, says so in a toast instead of navigating
- Export the open note (new in v2.1.0): an Export menu in the editor footer saves the open note as a plain text file (title first, then the body with checklist items as ballot box lines), as a real Word .docx document generated in the page with no library, or as a PDF through a clean print view the browser saves
- Import notes (new in v2.1.0): the Import button in the notes list toolbar turns .txt, .docx, and .pdf files into notes in the current notebook. Text files split into paragraphs, Word files are unzipped and converted in the page, and each PDF becomes a note with the file attached through the Google upload flow. Several files can be imported at once, and any file that fails is named in the closing summary
- More Insert items (new in v2.1.0): a starter table with a header row, a code block, and inline code join attachments, links, dividers, and the date and time in the Insert menu
- A full formatting toolbar (new in v1.3): an Insert menu (attachments, links, checklists, dividers, date and time), text styles (headings 1 to 3, quote, code block), font family and font size pickers, text and highlight color palettes with custom colors, strikethrough, text alignment, indent and outdent, and remove formatting. Fonts, sizes, and colors are saved as inline CSS styles in the note body, never as font tags, so formatted notes render the same on every device
- Attachments and inline images (new in v1.2): files are stored in your own Google Drive, in an attachments subfolder of the same SnakeScale Notes folder that holds your notes, and your notes keep only a small reference to each file. The same single Google sign in covers notes and attachments. Attach from the Insert menu, by drag and drop, or by pasting an image. Publisher setup for the sign in button is a one time job for the app owner: see [ATTACHMENT_PROVIDERS_SETUP.md](ATTACHMENT_PROVIDERS_SETUP.md). End users never register a developer app.
- Attachments where you left the cursor (new in v1.6): files attached from the Insert menu or file picker are inserted at the caret position you had when you started attaching, and files dropped onto the editor land at the drop point. A run of several files inserts in order at that spot
- Inline PDF preview (new in v1.6): PDF attachments get a Preview toggle on their card. Expanding it fetches the document on demand and shows it right inside the note, in the place where the attachment sits, so a PDF can be read without downloading it first. The preview is view only state; it is never written into the saved note file
- Movable, resizable attachments (new in v1.6): attachment blocks can be dragged to a new position inside a note (on touch screens, cut and paste moves them instead). Clicking an inline image selects it and shows a corner handle; dragging the handle resizes the image, and the chosen width is saved in the note so it renders the same size on every device
- Undoable attachment deletion (new in v1.7): removing an attachment, from its Remove button, the image menu, or the Delete and Backspace keys, takes it out of the note at once and opens a five second undo window, announced by a toast at the top of the window with the file name and an Undo button. The file is deleted from your Drive only when the window closes; Undo (or the block coming back, for example through the editor's own undo) cancels the deletion completely, and if the cloud delete cannot happen the attachment is restored and kept
- Inline images, no card (new in v1.7): image attachments sit in the note as plain images in the text, with no border, no card frame, and no name bar. File attachments, including PDFs with their inline preview, keep the card look
- Image grips and a three dot menu (new in v1.7): clicking an image selects it with four corner grips for resizing (any corner works, proportions are kept) and a three dot button at its top right. The menu opens the image full size, downloads it, applies quick sizes (25, 50, or 100 percent of the note column), or removes it through the undoable deletion above. A freshly pasted or dropped image can be selected, moved, and resized right away, without reopening the note
- Checklists without bullets, with real Enter behavior (fixed in v1.6): checklist items no longer show a stray list bullet in front of the checkbox, and pressing Enter at the end of a checklist item starts a fresh checklist item. Enter on an empty checklist item leaves the checklist, like other note apps
- A branded loading screen (new in v1.6): an animated tile S logo with a plain status line covers sign in and sync, and the note list fills in from the device cache behind it, so connecting never means staring at a blank screen. The sidebar shows the running app version at the bottom
- Pinned notes, trash with restore, and delete forever
- Archive (new in v1.5): tuck notes out of the way without deleting them. Archived notes move to their own archive folder and Archive view, stay out of the regular lists and search, open read only, and unarchive back to the notebook they came from at any time. Moving a note to Trash, restoring it, and deleting it forever also update the screen instantly now, with the storage work finishing in the background
- No app password, ever: sign in with Google is the only sign in. The Google token lives in memory while you use the app, the stored copy is encrypted, and a random device key encrypts the token store and the local note cache on that device. That device key is not a login and does not protect against someone using your unlocked browser profile
- Offline reading and editing from the local cache, with queued changes synced when you reconnect
- Conflict safety: if a note changed somewhere else, saving creates a conflict copy instead of overwriting it
- Note version history (new in v2.8.0): changing a previously saved note stores its previous state as a restorable version (at most one per 10 minutes, kept up to the count chosen in Settings). The History button in the editor footer previews versions read only and restores one after preserving the current note as a new version first
- A Settings dialog (new in v2.8.0): theme as a Light and Dark segmented control, Refresh connection, and the versions per note count live in one dialog opened from the sidebar menu, ready for future settings to join them
- Light and dark themes in the Deep Forest palette

## How to use it

1. Open the live app link above.
2. On the setup screen, continue to Google sign in. There is no SnakeScale app password and nothing to fill in.
3. Click Sign in with Google and approve access. SnakeScale creates a folder named SnakeScale Notes in your Drive for your notes, and attachments live in an attachments subfolder of that same folder, with the same sign in.
4. Start writing. On later visits SnakeScale first tries a silent Google sign in renewal; if that is not available, it shows the Sign in with Google screen. Use Sign out in the sidebar to clear this device's local copies, the stored sign in, and the device key while leaving the Drive notes untouched.
5. On other browsers, repeat the setup and sign in with the same Google account.

## How your data is stored

Everything lives in one folder in your Google Drive, named SnakeScale Notes.

- One folder per notebook inside a notebooks folder
- One Markdown file per note, with simple front matter and an HTML body
- A trash folder for deleted notes, an archive folder for archived notes, and an index.json the app can rebuild from the folders at any time
- A versions folder (new in v2.8.0) with one JSON file per note holding that note's saved version history: previous titles, bodies, tags, and attachment references, newest first. The folder is created only when a note first gains a version, and index rebuilds ignore it just like the attachments folder
- Attachments are different on purpose: the binary files live in an attachments subfolder of the same SnakeScale Notes folder. The note file stores only a one line attachments list in its front matter (provider name and file ID) plus a placeholder in the body where the image or file card appears
- Upgrading from a version before v2.0: attachments used to live in a separate top level folder named SnakeScale Notes Attachments. Those files keep working where they are, because notes reference them by Drive file ID. On your first sign in after the upgrade, SnakeScale makes one best effort pass to move them into the new attachments subfolder; the old folder is left in place for you to remove when you are ready

## Privacy and security notes

- Note sync talks to Google Drive from your browser, and Google's sign in script is loaded from Google only at the moment you click Sign in with Google. SnakeScale can only see the Drive files it created (the drive.file permission), not your whole Drive.
- The app ships with the publisher's Google OAuth client ID built in (new in v1.4.2), so nobody is ever asked for a client ID. That ID is a public identifier, not a secret: Google locks its use to the web origins the publisher registered in Google Cloud, so it cannot be used to sign anyone in from anywhere else. If you fork SnakeScale, register your own OAuth client in Google Cloud (free) and either replace the PUBLISHER_GOOGLE_CLIENT_ID constant in the app file, or set an override in the app settings value state.attach.googleClientId, which sign in still honors (there is no settings field for it in the app).
- Local copies on a device are encrypted with that device's random key, but the key lives on the same device. It scrambles local copies against casual snooping; it is not a login and it does not protect against someone using your unlocked browser profile. Sign out clears those local copies.
- Link info lookups (new in v2.9.0): when a link is shown as a Mention or a Preview, SnakeScale looks up that link's address through Microlink (api.microlink.io) to fetch the page's title, description, cover image, and site logo. Only the link address is sent, never note text or Drive data. The result is saved in the note itself, so a link is looked up once, not on every view, and Text links are never looked up.
- Settings or storage left on a device by a version before v2.0 (including an old app password vault record) are cleaned up automatically on first load; your Google settings, cache, and notes are not affected.
- SnakeScale Notes is not affiliated with Evernote Corporation.
